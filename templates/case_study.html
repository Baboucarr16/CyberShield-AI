Case study

How CyberShield catches a phishing URL

A walkthrough of the full detection pipeline — from raw link to explainable verdict — using a realistic attack example.

The suspect link

http://free-paypal-bonus-login.secure-update.example.com
Verdict: phishing Rule subtotal: 5 / 10

This disguised link mimics a PayPal promotion. Here is exactly what the engine sees.

  1. 1 Feature extraction

    The URL is parsed into measurable signals — no page visit required:

    FeatureObservedWhy it matters
    Protocolhttp (no TLS)Login pages without HTTPS are a classic red flag. (+2)
    Length56 characters (rule fires past 75)Long URLs can hide the real domain — this one scores on other signals instead.
    Hyphens4Stacked hyphens mimic brand + action phrasing. (+1)
    Dots / subdomains3 dots (rule fires past 4)Within the normal range here — no points from this check.
    Suspicious wordsfree, bonus, login, secure, update, paypalUrgency + brand + reward language, capped at +2.

  2. 2 Rule scoring

    Each matched rule adds weight. This URL accumulates 5 points from rules alone:

    • ! Uses HTTP instead of HTTPS +2
    • ! Contains multiple hyphens +1
    • ! Contains suspicious keywords +2

  3. 3 Decision & guidance

    Rule subtotal 5 ≥ 4, so the verdict is phishing. The Random Forest estimates about 48% phishing likelihood for this URL (roughly 3 model points on the shared scale), so the rule subtotal of 5 still decides the final combined score of 5/10. The report then tells the user what to do: do not sign in, verify through the official app, and report the message.

Key takeaway

Attackers combine one trusted cue (a familiar brand word) with several structural tricks (HTTP, hyphens, subdomains, urgency). CyberShield wins by scoring the structure, not the story — and by showing its work.
